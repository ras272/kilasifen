La carga del PKCS#12 requiere `secrets:write` y usa `multipart/form-data`.

```bash
curl -X POST https://TU_API/v1/emitters/EMITTER_ID/certificates \
  -H "X-API-Key: $KILA_API_KEY" \
  -F "logical_name=principal" \
  -F "password=$PFX_PASSWORD" \
  -F "file=@certificado.pfx;type=application/x-pkcs12"
```

Antes de activarlo, KilaSifen comprueba:

- estructura PKCS#12 y contraseña;
- presencia de clave privada RSA de al menos 2048 bits;
- vigencia temporal del certificado;
- RUC detectado contra el RUC del emisor;
- tamaño máximo configurado para el upload.

Los bytes del PFX y su contraseña se cifran antes de persistir. Ninguna
respuesta API devuelve el material ni su contraseña.

## Timbrado

Creá el timbrado con su vigencia y rangos, y activalo sólo después de revisar
establecimiento y punto de expedición. La numeración posterior se reserva de
forma atómica en el servidor.
